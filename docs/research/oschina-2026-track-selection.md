# 2026 上海开源软件应用创新大赛：AI Aegis 赛道选择研究

> 调研日期：2026-09-20（北京时间）  
> 结论依据：仅使用[赛事官网](https://www.oschina.net/os2026/)及官网直接调用的 OSCHINA 官方内容接口、官方赛题附件。页面内容可能继续更新，报名提交前应再核对一次。

## 一、结论先行

AI Aegis 最推荐报名：

**开源 AI 工具赛道 → AI 编程、调试与可观测工具（自主选题）**。

推荐把作品定义为：

> 面向企业自研 Agent 与 AI 编程 Agent 的开源运行时安全治理与可观测平台。通过声明式 Manifest、五段式 PreTool 安全管线、可解释策略决策、审计日志和管理员控制台，使 Agent 的工具调用可约束、可追溯、可验证。

推荐排序：

1. **开源 AI 工具赛道 / AI 编程、调试与可观测工具 / 自主选题**：现有产品无需改题，开发者可直接安装使用，五段管线、审计日志、后台和 Agent 接入正好形成完整工具产品。
2. **智算云赛道 / RAG、智能体框架与 MLOps / 自主选题**：若重点改为企业级 Agent 运行时基础设施、统一策略控制面、规模化治理和私有部署，则匹配度也很高；但官网对该赛道的核心表述是“支撑 AI 应用开发与运行的组件、框架或平台”，AI Aegis 若只展示终端安全工具，容易显得偏离云平台基础设施。
3. **智算云赛道 / DaoCloud MatrixHub 企业命题**：官方命题与 AI Aegis 都强调安全准入、策略、可解释报告、审计与治理，商业落地机会强；但命题对象是“模型制品恶意内容扫描”，不是“Agent 工具调用治理”，必须基于 MatrixHub 做大量定向开发，属于产品转向而非原项目自然参赛。
4. **AI+ 工业软件赛道**：除非补充明确的制造、能源、建筑等工业场景，并与 CAD/CAE/EDA 或工业互联网平台深度集成，否则不建议。

## 五、报名限制与参赛承诺

1. 个人或团队均可报名。
2. 团队人数官网仅写“**建议 3–5 人**”，不是硬性上限；须明确负责人 1 名。
3. **每个项目只能选择一个赛道**。
4. 同一主体可以提交多个项目参加不同赛道。
5. 报名表要求参赛者承诺项目原创；使用的第三方开源代码及素材均已合法授权，不侵犯第三方权益并符合法律法规。
6. 参赛者同意组委会为赛事宣传和成果展示目的，对作品享有非独家、免费的使用权；违规或侵权时，组委会可取消资格及奖项。
7. 入围团队须参加 10 月 29 日线下路演。

注意：赛事官网没有声明“每人最多参加几个项目”、强制团队人数、限定 Gitee/GitHub 平台或必须选企业赛题，因此不应自行添加这些限制。

## 六、作品、开源与材料要求

### 作品要求

- 项目应具备开源基础、技术创新性和产业应用价值。
- 代码仓库须包含**完整、可运行的代码**。
- 项目需能通过介绍文档讲清背景、技术架构、应用场景和创新点。
- 演示视频需展示核心功能与完整使用流程。
- 如选择企业命题并指定开发工具，还须服从对应任务书。
- 开源 AI 工具赛道特别关注完整产品形态、开箱即用、易用性、文档完善度和真实使用案例。

### 开源要求

官网没有公布强制许可证名称，也没有规定仓库必须托管于某个平台。但评分明确考察：

- 开源协议及第三方依赖是否合规；
- 贡献机制是否明确；
- 文档是否规范；
- Issue/PR 响应机制；
- 新项目的治理规划，或已有项目的实际社区运营。

因此 AI Aegis 应在提交前补齐 LICENSE、第三方依赖及许可证清单、CONTRIBUTING、CODE_OF_CONDUCT、SECURITY、Issue/PR 模板、版本路线图和维护者/治理说明。这里是针对评分项的备赛建议，不是官网新增的形式门槛。

### 报名及提交材料

1. 在大赛官网填写报名表，提交后等待组委会邮件确认。
2. 收到确认邮件后，按指引准备：
   - 代码仓库链接（完整可运行代码）；
   - 作品介绍文档，推荐 PDF（背景、技术架构、应用场景、创新点）；
   - 作品演示视频链接（核心功能、使用流程）。
3. 按官网要求打包附件，于 **10 月 11 日 24:00 前**发送到 **oscc@oschina.cn**。

## 八、为什么首选“开源 AI 工具—AI 编程、调试与可观测工具”

### 1. 官网关键词与产品能力逐项对应

| 官网关键词 | AI Aegis 现有能力 |
|---|---|
| AI 编程工具 | 面向 Claude Code、Codex 等 Agent 开发/执行流程的安全接入 |
| 调试 | 五段管线提供每一步判定和阻断原因，适合复现、分析策略误报和漏报 |
| 可观测 | 结构化、可审计日志，决策信号、Manifest 版本和调用轨迹可追溯 |
| 直接面向用户 | 开发者本地框架、管理员后台和标准接入 SDK 均有明确用户界面 |
| 完整产品形态 | 检测内核、Manifest、审计、后台、报告和 Demo 可组成端到端产品 |
| 开箱即用 | 可通过模板、默认策略、示例 Agent 和一键攻击回放证明 |
| 实际使用案例 | 可用真实 AI 编程 Agent 的文件、Shell、Git、MCP 工具调用演示 |

### 2. 比“智算云”更低的叙事风险

智算云同样写明“智能体框架与 MLOps”，但其上位定义强调“支撑 AI 应用开发与运行的组件、框架或平台”，并与算力调度、训练推理、多云/边云并列。若 AI Aegis 的 Demo 重点是开发者安全工具和管理员控制台，报名开源 AI 工具赛道更符合评委预期，不需要把产品硬包装成云基础设施。

### 3. 选择“自主选题”比硬套企业命题更稳

MatrixHub 企业题虽有扫描、准入、审计和治理等相近概念，但被保护对象是模型仓库中的模型文件与版本；AI Aegis 被保护对象是 Agent 的工具调用和运行权限。二者安全对象、接入点和验收用例不同。除非团队愿意真正完成 MatrixHub 集成及模型文件扫描，否则自主选题更能保留现有技术积累并提升完成度。

## 九、报名表与路演建议用语

### 推荐项目名称

**AI Aegis：面向企业自研 Agent 的开源运行时安全治理与可观测平台**

### 推荐所属方向

**开源 AI 工具赛道 — AI 编程、调试与可观测工具 — 自主选题**

### 一句话价值主张

> 在 Agent 调用 Shell、文件系统、Git、MCP 和企业内部工具之前，通过 Manifest 与五段式策略管线完成最小权限判断、风险确认和阻断，并将全部决策转化为可审计证据。

### 演示闭环

1. 导入一个企业自研 Agent 或 AI 编程 Agent。
2. 为其生成/配置 Manifest 权限。
3. 执行正常开发任务，展示低摩擦允许。
4. 注入越权、敏感数据外传或高危命令场景，展示确认/阻断。
5. 在管理员后台回放完整证据链，定位操作者、Agent、工具、参数摘要、策略版本和处置结果。
6. 展示 Benchmark：安全召回率、误报率、决策延迟及与无防护/简单黑名单方案的比较。

## 十、最终选择

如果报名表今天就要填写，建议直接选：

> **开源 AI 工具赛道 → AI 编程、调试与可观测工具 → 自主选题。**

只有在以下条件同时成立时才改选智算云：作品会被重构为可供多个团队和多种 Agent 统一接入的运行时安全基础设施，能够演示集中策略下发、多租户、私有部署、规模化可观测及与 MLOps/Agent 平台的稳定集成。否则首选方案与产品现状、材料完成度和官网赛道语义的重合度最高。
