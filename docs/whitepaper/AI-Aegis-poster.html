问题 · Agent 攻击面

  • 直接提示注入 — 指令覆盖 / 系统提示提取
  • 间接与工具结果注入 — 恶意指令藏在 MCP 返回值
  • 权限试探与升级 — 跨轮次逐步索取更高权限
  • 数据外泄 — 敏感读取 → 外部写入序列
  • 不可逆破坏 — 删除 / 发布 / 强推 / 删凭据
  • 供应链投毒 — 被污染的 Skill / MCP 工具

现有方案 · 四类不足

  • 单轮视角：看不见跨轮试探与主题偏移
  • 裁决不可复现：交给 LLM 判官，无法回归与定责
  • 事后而非事前：告警时副作用已发生
  • 运营与防护割裂：缺少统一证据链

系统架构 · 四层

  • 接入层 — 原生 Hook / 插件 / 代理 / 框架 SDK / MCP
  • 本地引擎 — 规则 + Guardian ML + 五段管线 + 治理
  • 审计存储 — SQLite + SHA-256 哈希链
  • 运营平面 — LangGraph · RAG · 记忆 · 免疫 · 审批

集成与部署

  • 一键安装 — pip install ai-aegis[app]
  • 容器 — 4 份 Compose（demo / agent / self-host / nginx）
  • 插件 — Claude Code · Codex · Copilot CLI · Cursor · OpenClaw
  • SIEM — Splunk / Datadog / Sentinel / QRadar / Chronicle / OTLP

核心创新

  • ① 证据/裁决分离 — 模型只给布尔/枚举，分数与裁决由代码定
  • ② 会话级五段管线 — 从单轮升级到跨轮状态机
  • ③ 三重正交防线 — 规则 + 离线 ML + 会话状态
  • ④ 不可绕过 Manifest — 插件自报不能放宽
  • ⑤ 只升不放 — 只能升级拒绝，绝不静默放宽
  • ⑥ 受治理免疫学习 — 人工激活 · 贡献封顶 · 不能独立阻断
  • ⑦ 统一哈希链审计 — 自动判定与人工操作同链
